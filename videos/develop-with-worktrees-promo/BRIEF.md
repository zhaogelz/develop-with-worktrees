# 创作目标

先让观众认出自己的麻烦：AI 都说写好了，最后却要自己收拾一堆改动。用同一个项目里的登录页、接口、文档三个任务，演示 DWW 如何准备独立目录、保存任务记录、检查组合后的结果，最后合回本地分支。

首页与视频使用同一主张：“多个 AI 同时开工，少一点互相收拾残局。”视频的记忆点是“分开做，一起检查，再合回去”。

# 内容边界

- 36 秒、1080×1920、30 FPS、无配音和音乐；手机静音观看也能理解。
- 画面是明确标注的流程示意，不冒充产品真实界面或本次运行结果。
- 独立目录避免工作中的文件互相覆盖；合并仍可能冲突。
- 检查按项目配置执行，不宣传“检查过就绝无 bug”。
- 冲突或检查失败时保留现场，成功前不推进主线；修复后才能继续。
- 任务可能等待批次集成，不能把提交完成画成已经交付。
- DWW 负责本地 Git 流程；任务编排仍由 Codex 等宿主负责。
- 不新增性能数字、用户数量、虚构评价或“绝不会改乱”等保证。
- 只修改可编辑源工程和发布资料；预览后再决定导出，发布另行授权。
