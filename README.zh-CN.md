# Develop with Worktrees

一个面向 Codex 的本地优先工作流 skill：用少量固定 Git worktree 槽位，让单人 AI 开发同时保持速度、隔离性和可恢复性。

仓库完成一次初始化后，所有会修改文件的开发任务都会领取独占的短期分支和可复用槽位；只读分析不占槽位。任务提交后先同步本地默认分支、执行已获批准的验证，再通过 FIFO 集成门禁合入。

## 它解决什么问题

直接使用 `git worktree` 只能解决目录隔离，不能自动解决任务归属、依赖缓存、端口冲突、并发合并、验证复用、失败恢复和安全清理。本项目把这些约束归纳为可重复使用的 Codex skill。

第一版默认规则：

- 3 个延迟初始化的固定槽位，可配置为 1～5 个。
- 只操作本地，不自动 fetch、pull、push、创建 PR，也不收集遥测。
- 即使主工作区有未提交改动，Start 仍从本地默认分支的已提交 HEAD 建任务；这些脏改动不会进入任务，Finish 则必须等主工作区干净后才能合入。
- 每个任务独立分支；不 squash、不 rebase、不 amend、不改写历史。
- Ready 负责同步与验证，Finish 通过 FIFO 队列串行集成。
- 候选证明精确绑定候选代码与主线；项目 profile 证明绑定声明路径内的全部已跟踪输入、规则、命令、锁文件、工具、平台和持久日志，只有输入闭包完全一致才允许跨任务复用。
- 提交前检查敏感文件和常见密钥格式，验证日志在写入前脱敏。
- 验证失败、冲突或未知文件都保留现场，不擅自清理。

## 环境要求

- Git
- [uv](https://docs.astral.sh/uv/)
- 支持 skill 的 Codex

不要求 PowerShell 7，也不要求用户预先安装 Python。运行器采用 PEP 723，由 uv 直接执行。如果电脑已经安装 uv，就直接复用现有 uv；不会重复安装另一份，也不会改写全局 Python 环境。

## 安装

只需将 `skills/develop-with-worktrees` 安装或复制到 Codex skill 目录。项目本身不需要安装 Python 包。

当前仓库可直接作为后续发布到 GitHub 的源码仓库。安装 skill 不会自动改写所有项目；当 Codex 接到某个 Git 仓库的修改任务时，skill 会被隐式触发，并在该仓库首次使用时进行一次初始化确认。以后正常描述开发需求即可，不必每次说“使用 worktree”。

## 新仓库首次确认

skill 会先检查仓库现有规则和验证入口：

1. 发现测试、lint、构建或验证命令后，展示给用户确认一次。
2. 用户同意后，创建一个仅包含 `.solo-ai/config.toml`、`.solo-ai/verification.toml` 和 `AGENTS.md` 受管区块的本地初始化提交。
3. 如果没有有效验证命令，必须明确接受静态模式；结果只能称为“仅静态检查”，不能称为“测试通过”。
4. 如果仓库已有成熟 worktree/智能体编排流程，则进入 compatible 模式并服从原流程，不叠加第二套槽位管理。

初始化提交不会自动推送远端。它进入本地默认分支，是为了让所有工作树获得同一套仓库级规则；运行状态、租约、日志、证明和个人选择仍只保存在 `.git/solo-ai`。

## 日常流程

```text
只读任务 -> 原地分析，不领取槽位
修改任务 -> Start -> 开发与定向检查 -> Commit -> Ready -> FIFO Finish
                                      失败 -> 保留现场 -> Recover -> 继续
```

多个槽位同时修改不会自动互相合并。每个任务独立提交，完成后依次进入 Finish。若前一个任务已推进默认分支，后一个任务会先把最新默认分支普通 merge 到自己的任务分支；有真实冲突就保留现场处理，没有冲突才继续验证和快进集成。

三个槽位首次使用可能较慢：源码检出是延迟的，各槽位依赖也在真正运行项目时才准备。之后槽位会保留自己的 `.venv`、`node_modules`、`.env*`、`.cache` 和 `.tmp`，以换取后续速度；不会从主工作区复制这些内容。

## 本地状态说明

会提交到仓库的内容：

- `.solo-ai/config.toml`：槽位数量、分支前缀、端口区间、安全策略等团队规则。
- `.solo-ai/verification.toml`：路径对应的验证命令。
- `AGENTS.md` 受管区块：要求所有修改任务使用该流程。

仅保存在本机 Git 公共元数据目录的内容：

- 槽位和任务状态、租约、FIFO 队列。
- 依赖缓存与槽位环境。
- 端口和精确进程身份。
- 脱敏验证日志与可复用证明。
- 用户对命令的批准和本机停用选择。

这意味着规则可以随仓库共享，而机器路径、缓存、端口和日志不会污染提交，也不会在不同电脑之间产生冲突。

用户可执行 `disable` / `enable` 进行本机个人停用或恢复；该选择只写入 `.git/solo-ai/preferences.json`，不会修改团队共享规则。

## 与 Worktrunk 的关系

[Worktrunk](https://github.com/max-sixty/worktrunk) 是成熟、通用、交互体验优秀的 worktree CLI，擅长 hook、路径模板、shell 集成和人工操作效率。本项目更窄、更偏执行政策：目标是让 Codex 在单人 AI 开发时默认遵循固定槽位、任务租约、FIFO 合入、验证证明、安全扫描和失败保留。

本项目借鉴其“命令简单、脚本友好、快速切换”的思路，但不采用自动远端操作、默认 squash/rebase、清理未知文件或绕过验证门禁。这两者可以互补；若仓库已由 Worktrunk 等成熟方案管理，本 skill 会选择兼容而不是接管。

```text
uv sync --dev
uv run pytest
uv run <skill-creator路径>/scripts/quick_validate.py skills/develop-with-worktrees
```

测试只使用临时 Git 仓库，不会拿当前业务项目当测试场。CI 覆盖 Windows、Linux 和 macOS。

## 第一版边界

第一版以保守可靠为主，适合本地试用。敏感内容扫描只是门禁，不替代专业 secret scanner；compatible 模式只让位于已有编排器，不包装或改造对方流程。
