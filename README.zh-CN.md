# Develop with Worktrees

`0.3.0-beta.5` 是一套默认不让并行 AI 改动互相覆盖的本地 Git 工作流。生命周期内核不绑定 Codex；本插件提供 Codex 的首次选择、多 AI 指挥中心、技能和写入保护适配。

## 复杂任务只用一个中央对话

简单任务仍然简单：一个 AI 走原有隔离生命周期。复杂目标时，Codex 先用通俗语言给出短计划，等待你一次确认；确认后中央对话才会派发能独立验收的任务，同时开发数最多是 `min(5, 已配置槽位, 当前空闲槽位)`。

指挥中心只在 Git common-dir 保存精简的任务图、依赖、状态、生命周期/证明引用和关键决定，不保存聊天记录、原始推理、lease 或密钥。暂停、取消或换一个中央对话都会保留分支和文件；取消不会删除工作。

同一文件的预判默认允许乐观并行。只有迁移、锁文件、共享契约等明确的高风险资源才串行。Git 可干净合并且 Ready/Finish 通过时只在本地合入；文本或语义冲突会进入一条新的修复任务，不会被猜测解决。默认没有审查 AI、常驻后台、push、PR、部署或全仓库最终测试。

## 仓库已有成熟工作流时始终优先

在任何仓库选择前，极小的只读路由会检查是否已有成熟工作树或编排流程。命中后 DWW 静默让路：不弹三选一、不写 DWW 状态，只遵循仓库自己的指令。该结果高于之前保存的本次或长期当前目录选择；这些本地记录保持不变，只有成熟工作流标记移除后才可能重新生效。

受信任的 `SessionStart` Hook 通常只注入一次该路由。Hook 上下文不可用时，技能只运行一次轻量 `dww route --json`，不会加载完整 `doctor`。

## 第一次修改时，只问一个问题

```text
此仓库怎么修改？

1. 每个任务使用独立目录（推荐）
   任务互不影响，完成后自动合回。

2. 这一次直接改当前目录
   只跳过这一次，下次还会询问。

3. 以后都直接改当前目录
   记住此选择，这个仓库不再询问。

只影响本机，可随时修改。
```

- 选 1 后，普通修改自动在独立目录完成，结束时只在本地合回当前派生分支；不会把 `main` 写死。
- 选 2 后，这次任务就在当前目录按普通方式修改，插件不创建配置、不启动任务，也不要求 Commit/Ready/Finish。下次新开任务再问。
- 选 3 后，只在这台机器的此仓库记住“直接改当前目录”；不提交任何设置，换电脑或换克隆目录仍由各自选择。

如果没有发现自动测试，选 1 仍会隔离任务并在内部执行基础检查，不会再弹出一个确认。用户以后说“这个仓库以后使用独立目录开发”或“以后直接在当前目录开发”即可改变本机选择。

## 选独立目录后会发生什么

```text
route → start → 只在返回的目录修改 → commit 精确路径
       → plan / verify → ready → finish
```

- 每个普通任务独占一个可复用目录和租约；Finish 会在本地快进前持久化精确候选事务，Recover 根据 Git 祖先事实只完成中断收尾，不会把期间出现的新候选混进旧任务。
- Abandon 遇到未提交的 tracked 改动、受保护文件、同路径对象替换或其他活跃任务引用时会保留现场并停止；不会用 reset/clean 强行吞掉内容。
- Ready 在取得机器验证名额后核对基线；并发任务推进主线时，同一次 Ready 自动同步并复用精确内容证明，最多重试 5 次，不再把旧基线证明交给 Finish 重跑。
- schema 3 验证会按改动路径选择 profile，并走本机 machine-global weighted FIFO 验证队列。预计慢时只提示拆分映射、减少重复准备，绝不偷偷少测。
- Finish 不删除依赖、缓存或测试数据；清理只能手工 `prune-slot`，计划绑定槽位世代且只能执行一次，并先看精确计划再确认。移动或逐项删除期间即使进程退出，也只会从同一清单继续，不会另起计划绕过现场。

`start --in-place` 仍保留给明确要求“在当前目录但仍要 DWW 的精确提交、验证和 Finish 保护”的高级兼容场景；它不是选 2 的含义。

Codex 中，`PreToolUse` 受信任后会在支持的本地工具路径上真正拒绝受保护工作目录的未授权写入（包括 `apply_patch` 和常见 Bash 写命令），不是只提醒。它不是操作系统沙箱：少数专用路径可能不经过钩子；只有后续又经过钩子的操作或执行 `doctor` 观察到逃逸脏改动时，才会保留并记录警报，不能承诺立即发现。Codex 按精确钩子定义保存信任，普通插件更新保持稳定定义，不重复要求用户操作；只有首次安装或有意改变定义才需要审查。Codex 确实提示待审时，AI 先说明变化并询问一次，获准后在宿主界面控制可用时自行完成 `/hooks`，不让用户逐步点击；当前界面不能由 AI 控制时必须说明限制，也不能声称硬保护已启用。

## 安装

```text
codex plugin marketplace add zhaogelz/develop-with-worktrees --ref main
codex plugin add develop-with-worktrees@develop-with-worktrees
```

插件和 DWW 生命周期不会自动升级，也绝不会 fetch、pull、push、创建 PR、rebase、squash、amend 或改写历史。Finish 成功后，用户可以明确要求从干净基线工作区执行一次独立的普通推送；必须先 dry-run、只推当前分支且禁止强推。
